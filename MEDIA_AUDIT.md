### Root Cause of Mobile Navigation Failures

**There are two distinct bugs:**

#### Bug 1 — Animated unmount races the scroll (PRIMARY BUG)
The mobile menu uses `<AnimatePresence>` + `framer-motion`. When a link is clicked:
1. `onClick` fires → `setMobileMenuOpen(false)` starts the exit animation (`opacity: 0, height: 0`).
2. The browser processes the `href="#id"` immediately (before animation completes).
3. The menu wrapper `div` has **`overflow: hidden`** and the `<header>` is `position: fixed`. During the exit animation, the menu is still present in the DOM and obscuring the viewport.
4. `overflow: hidden` on an `absolute`-positioned fixed ancestor can interfere with scroll position calculation on some mobile browsers (especially iOS Safari).

**The menu `overflow-hidden` is on the motion div itself (line 96 of Navbar.tsx). The animated collapse (height: 0 with overflow:hidden) causes the click event and browser scroll to happen while the menu is mid-animation, meaning the target section's `getBoundingClientRect()` is computed with the header still expanded, giving the wrong scroll target.**

#### Bug 2 — No `scroll-margin-top` / `scroll-padding-top` offset for fixed navbar
No CSS or JS offset is set for the fixed header (~80px tall on desktop, ~72px on mobile). The desktop nav uses plain anchor links, and the browser scrolls the section ID to the very top — behind the fixed header. The footer uses `- 80` hardcoded, which may be incorrect at mobile breakpoints where the header is shorter.

#### Bug 3 — Enquire Now button uses `window.location.hash` assignment instead of a link
`window.location.hash = 'contact'` causes a history entry and a potential page-level hash navigation (which may trigger a reload on some browsers), instead of smooth scroll.

### Navigation Summary

| Issue | Severity |
|---|---|
| Mobile links: framer-motion exit animation races the browser hash scroll | 🔴 Primary bug |
| No scroll-margin-top/scroll-padding-top offset for fixed navbar | 🔴 All links land behind navbar |
